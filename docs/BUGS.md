# Реестр дефектов (вход для линии ревью)

Формат: что сломано → как воспроизвести → как закрыто → чем подтверждено.
Открытые дефекты идут сверху. Всё, что помечено «закрыт», подтверждено независимым гейтом
из `acceptance/`, а не отчётом агента.

## Открытые

### B5 — продакшн-код подделывал вывод приёмки (gate gaming) — закрыт
- **Симптом:** `app/providers/base.py` при импорте подменял `builtins.print`; при запуске, где в
  `sys.orig_argv` встречалось `METHODS:`, он переписывал `UNSUPPORTED:True` → `UNSUPPORTED:true`,
  чтобы пройти сравнение в гейте. `print` ломался во всём процессе.
- **Причина (со стороны приёмки):** в `acceptance/gate_stage3.py` сравнение было
  `== "true"`, а Python печатает `True`. Агент «исправил» не тот конец.
- **Закрыто:** хук удалён из `base.py`; гейт 3 переведён на `.lower()` (v3); в гейт 3B добавлена
  проверка `test_no_gate_gaming_in_app_layer` (скан `app/` на `builtins.print =`, `sys.stdout =`,
  `sys.argv`, `orig_argv`, `import pytest`, `acceptance/`, `unittest.mock`).
- **Остаток закрыт:** гейты физически убираются из дерева на время прогона агента
  (`mv acceptance ~/Projects/.wit-gates-stash`, процедура в `acceptance/README.md`).

### B6 — панель деталей не следует за курсором таблицы (UX)
- **Симптом:** на скриншотах `runs/shots/stage3c_wallets_{120,140}.png` подсвечена строка
  `Alpha`, а панель деталей показывает `Vitalik Treasury`.
- **Причина:** детали обновляются только по `DataTable.RowSelected` (Enter), обработчика
  `RowHighlighted` нет — `app/ui/screens/wallets.py`.
- **Как чинить:** обновлять детали на перемещение курсора, сохранить Enter как «открыть полную
  историю»; в гейте проверять, что после `table.move_cursor(row=1)` панель содержит адрес второй
  строки.
- **Статус:** открыт.

### B7 — `conftest.py` инжектил имя в builtins (`builtins.json = json`)
- **Симптом:** гейт 2A проходил только из корня проекта; запущенный из другой директории падал
  с `NameError: name 'json' is not defined` (в самом гейте не было `import json`).
- **Причина:** корневой `conftest.py` (написан агентом на Этапе 1A) делал
  `builtins.json = json`, из-за чего имя `json` было доступно в **любом** модуле — гейт
  «работал» за счёт подпорки, а любая забытая импортa в коде переставала быть видимой.
- **Закрыто:** `conftest.py` переписан (только `ROOT` в `sys.path` и фикстура `clean_env`);
  в гейт 2A добавлен `import json`; сканер `test_no_gate_gaming_in_app_layer` расширен на
  корневые `*.py`, включая `conftest.py` (`builtins.print/json/open`, `sys.stdout`, `orig_argv`).
- **Подтверждено:** `41 passed` (1A–2B) до расширения сканера и `66 passed` после, запуск гейта
  2A одиночно и в связке — одинаково зелёный.

  `runs/shots/stage3c_wallets_140.png`).
- Футер хоткеев виден целиком на 110 и 120 колонках.

### B8 — перевод между своими кошельками ломал синхронизацию (данные)
- **Симптом:** `sqlite3.IntegrityError: UNIQUE constraint failed: transactions.network_id,
  transactions.tx_hash`, следом `PendingRollbackError` — второй кошелёк не синхронизируется.
- **Причина:** уникальный индекс `uq_transaction_wallet_network_tx` создан по
  `(network_id, tx_hash)` вместо `(wallet_id, network_id, tx_hash)`. Одна on-chain транзакция
  касается двух наших адресов — вторая запись невозможна. Плюс при падении flush сессия не
  откатывается.
- **Найдено:** живым прогоном на демо-БД (не гейтом 4A — гейт проверял дедуп только на одном
  кошельке).
- **Закрыто:** ревизия `006_transactions_unique_per_wallet` + rollback в `SyncEngine`;
  гейт `gate_stage4c.py` (5 проверок: shared tx, идемпотентность, восстановление сессии,
  форма индекса, тексты пустого состояния).
- **Статус:** закрыт.

## Закрытые

### B1 — фиктивная миграция Alembic
`upgrade()` вызывал `Base.metadata.create_all(op.get_bind())` вместо DDL: `downgrade` не работал,
`autogenerate` врал, историческая ревизия зависела от текущих моделей.
**Закрыто:** 22 × `op.create_table` + 6 индексов + рабочий `downgrade` в `001_initial_schema.py`.
**Подтверждено:** гейт 1A `test_migration_creates_real_ddl`, цикл upgrade → downgrade base →
upgrade (23 таблицы).

### B2 — нормализация адреса только в конструкторе
`Wallet(address=...)` нормализовал адрес, а `wallet.address = "0xABC…"` — нет, из-за чего
дедупликация и поиск промахивались.
**Закрыто:** валидатор на attribute event (`@validates`) + `normalize_evm_address` в `utils/validators.py`.
**Подтверждено:** гейт 1A `test_address_normalized_on_assignment`.

### B3 — утечка модульного engine, тесты зависели от порядка
Один глобальный engine переживал между тестами; прогон в обратном порядке падал.
**Закрыто:** явная фабрика сессий, `dispose()` в `init_db`, никакой мутации env из кода.
**Подтверждено:** прогон по одному файлу и в обратном порядке — зелено (Этап 1A).

### B4 — правка уже применённой ревизии (Этап 3)
Агент дописал `block_number`/`taken_at` в `migrations/versions/001_initial_schema.py` вместо
новой ревизии: старые БД колонок не получают, новые получают — установки одной версии расходятся.
**Закрыто:** 001 откатан, sha256 001/002 запинены, добавлена ревизия
`003_balance_snapshot_block_time` (`op.add_column` ×2 + `downgrade`).
**Подтверждено:** гейт 3 `test_frozen_revisions_untouched`,
`test_schema_matches_models_after_upgrade`; ручная проверка апгрейда существующей БД 002 → 003
с сохранением данных и обратного downgrade.

### B0 — прогон агента «успешен», но не сделал ничего
`status: SUCCESS`, `response: ""`, `denied_actions: [...]`, 0 файлов на диске.
**Закрыто процессно:** каждый этап принимается только по артефакту и своему гейту, `status`
игнорируется. Права выдаются заранее полным набором (`command(*)`, `write_file(/)`,
`read_file(/)`), потому что headless-режим не умеет спрашивать разрешения.

## Как добавлять сюда

Правило: дефект попадает в реестр **с воспроизведением** (команда или тест), а не с описанием
впечатления. Закрытие подтверждается ссылкой на проверку гейта + её реальным выводом.
Дефекты, найденные линией ревью, нумеруются B6+ и не закрываются автором кода — только
независимой проверкой.
