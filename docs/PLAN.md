# Wallet Intelligence Tracker — план разработки и приёмка

Источник требований: `docs/spec.md` (ТЗ v1.0, 1028 строк).
Режим работы: AGY (Antigravity CLI) пишет код, Hermes планирует, ставит независимые
тесты-гейты и проверяет результат на диске. Лог решений и спорных моментов — `docs/DEVLOG.md`.

## Принципы процесса

1. **Один этап = один прогон агента.** Агент не переходит к следующему этапу, пока
   гейт текущего не зелёный.
2. **TDD.** Внутри этапа: сначала падающий тест, потом минимальная реализация,
   потом рефакторинг. Тесты агента живут в `tests/`.
3. **Независимый гейт.** Для каждого этапа Hermes пишет `acceptance/gate_stageN*.py`
   (pytest) до старта работ, фиксирует sha256 в DEVLOG. Агент не имеет права править
   `acceptance/`; при расхождении хеша гейт откатывается через git.
4. **Проверка по артефакту.** Отчёт агента — не доказательство. Доказательство — вывод
   `pytest`, `git diff`, чтение файлов самим Hermes.
5. **Спорные моменты** — в DEVLOG отдельным разделом «Открытые вопросы / решения»,
   с выбранным вариантом и обоснованием.

## Этапы

### Этап 1 — фундамент (разбит на 1A и 1B)

**1A. Каркас, конфиг, БД, модели**
- `pyproject.toml` (uv), зависимости по §6, dev-группа с pytest/ruff;
- структура каталогов по §7 (пустые пакеты, `__init__.py`);
- `app/config.py` — pydantic-конфиг из `config.yaml` + override из env, без секретов в yaml;
- `app/database/models.py` — все 21 сущности §8 (FK, индексы, unique, Decimal/Numeric);
- `app/database/session.py` — engine, `init_db`, контекстный `get_session`;
- Alembic: `alembic.ini`, `migrations/env.py`, первая ревизия;
- `app/utils/logging.py` — логи в `logs/`, маскирование ключей;
- `config.yaml`, `.env.example`, `.gitignore`, README-скелет;
- тесты: конфиг, схема, ограничения целостности, миграция с нуля.

**1B. Textual-приложение**
- `main.py`, `app/application.py`, `app/state.py`;
- 9 экранов §9 (dashboard, wallets, activities, projects, defi, networks, graph, import, settings);
- навигация: боковая панель, хоткеи `1–9`, `q`, `Esc`, `/`, `A`, `I`, `R`, `F`, `G`;
- статус-строка (состояние синхронизации, время обновления), `app.tcss`;
- тесты через `App.run_test()`: запуск, переключение всех разделов, выход, отсутствие блокировки.

**Результат:** запускаемое TUI с рабочей навигацией и локальной БД.

### Этап 2 — кошельки, группы, импорт
CRUD кошельков/групп (неограниченная вложенность), теги/заметки/соцссылки, поиск и
фильтры, история изменений метаданных, bulk import TXT/CSV/JSON с превью, валидацией
адресов, дедупликацией (address+network), отчётом ok/skipped/error, в worker'е без
блокировки UI. Удаление группы не удаляет кошельки (перенос в родителя/Unassigned).

### Этап 3 — EVM Data Providers
`providers/base.py` (интерфейс §4.2, явный `unsupported`), EVM JSON-RPC адаптер,
один explorer API (Etherscan v2 или Blockscout), native balance, транзакции с
пагинацией, timeout/backoff/rate limit/кэш, health check, сохранение в БД,
mock-тесты без сети (httpx.MockTransport).

### Этап 4 — синхронизация и активности
Sync Manager (asyncio), курсоры по (wallet, network, data_type), инкремент,
дедуп по (network, tx_hash, log_index), пауза/возобновление, прогресс, частичные
ошибки; Activity Tracker с разделением auto/manual, фильтры, подсветка кошельков проекта.

### Этап 5 — проекты и тестнеты
Каталог проектов, контракты по сетям, ручная и автоматическая привязка кошельков,
задачи/чек-листы, отчёт участия с полем `source` (detected/manual/task).

### Этап 6 — DeFi Analyzer
Токен-балансы, цены, подтверждённые позиции (отдельно от inferred/unknown),
агрегация по протоколам и сетям, история стоимости.

### Этап 7 — Relationship Graph
Модель связей с уровнем достоверности, построение графа (NetworkX), текстовое
представление и список соседей, фильтры, экспорт (JSON/HTML-заготовка).

### Этап 8 — финализация
Solana-адаптер, пользовательские сети, несколько RPC с фолбэком, бэкап/восстановление,
оптимизация, документация, проверка установки.

## Критерии приёмки (мой набор, проверяемый)

MVP = этапы 1–5. Пункт считается принятым только при зелёном гейте и ручной проверке
артефакта.

| # | Критерий | Как проверяется |
|---|---|---|
| A1 | `uv sync` и `uv run python main.py` запускают TUI; разделы 1–9 переключаются; `q` выходит | `pytest acceptance/` (pilot-тест) + ручной прогон |
| A2 | SQLite создаётся автоматически; `alembic upgrade head` работает с нуля; повторный запуск идемпотентен | гейт 1A; удаление БД и повтор |
| A3 | CRUD кошельков/групп; вложенность любой глубины; удаление группы не теряет кошельки | гейт 2 + тесты агента |
| A4 | Теги (M2M), заметки, соцссылки, поиск, фильтры | гейт 2 |
| A5 | Импорт CSV/TXT/JSON: превью, валидация, дедуп, отчёт ok/skipped/error; UI не блокируется | гейт 2 (fixtures), тест на worker |
| A6 | Провайдер-слой: общий интерфейс, ≥1 реальный источник EVM, `unsupported` явно, timeout/backoff/rate limit | гейт 3 (mock-транспорт, без сети) |
| A7 | Синхронизация инкрементальная, курсоры, дедуп событий, пауза/резюм, ошибки не валят приложение | гейт 4 (fake provider) |
| A8 | Активности: auto/manual раздельно, фильтры, поиск, детали транзакции | гейт 4 |
| A9 | Проекты: контракты, привязка кошельков, задачи, отчёт участия с `source` | гейт 5 |
| A10 | Тесты зелёные, `ruff check` без ошибок, зависимости зафиксированы | `uv run pytest -q`, `uv run ruff check` |
| A11 | README (установка/запуск), `.env.example`, `.gitignore` исключает `.env`, `data/`, `logs/`, `.venv` | гейт 1A + глазами |
| A12 | Секреты не попадают в логи и в git; ключи только через env | скан `logs/`, `git grep` по паттернам ключей |
