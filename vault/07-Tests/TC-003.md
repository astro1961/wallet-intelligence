# TC-003 — Пустые состояния: чистая БД без кошельков

## Предусловия
- Изолированная тестовая среда: чистая БД через фикстуру `clean_db` из `tests/e2e/conftest.py` (переменная окружения `WIT_DB_PATH` указывает на временный файл).
- База данных пуста: записи в таблице кошельков отсутствуют (фабрика `make_wallet` из `tests/fixtures/factories.py` не вызывается).
- Приложение `WalletTrackerApp` запущено в headless-режиме через Textual pilot (`App.run_test(size=(140, 40))`).

## Шаги
1. Запустить приложение с чистой тестовой базой данных.
2. Убедиться, что активен главный экран приложения (`app.screen.id == "dashboard"`).
3. Дождаться завершения начальной загрузки и рендеринга виджетов.
4. Найти виджет панели кошельков `#panel-wallets`.
5. Получить текстовое содержимое панели `#panel-wallets`.

## Ожидаемый результат
- Внутри панели `#panel-wallets` отображается текст-заглушка: `No wallets tracked yet` (полный текст: `No wallets tracked yet (press 'a' to add or 'i' to import)`).
- Отсутствуют аварийные завершения приложения, неотловленные исключения и пустые нерендерируемые области.

## Тестовые данные
- `clean_db` из `tests/e2e/conftest.py` — временный файл базы данных SQLite (`WIT_DB_PATH`).
- `tests/fixtures/factories.py` — модуль тестовых фабрик подключен в тестовом окружении, но создание записей кошельков намеренно пропускается для имитации нулевого состояния.

## Саммари (RU)
Тест-кейс проверяет корректность отображения пустого состояния (empty state) для панели отслеживаемых кошельков на экране Dashboard при первом запуске или отсутствии добавленных адресов в базе данных.

## Выводы (RU)
- Сценарий относится к классу граничных условий (P3, edge).
- Изоляция через `clean_db` гарантирует отсутствие побочных эффектов от предыдущих тестов или рабочей БД.
- Позволяет защитить пользовательский интерфейс от сбоев при пустых выборках данных.
