# BUG-001 — Dashboard не обновляет панель #panel-wallets при возврате на экран через nav_to

## Описание (RU)
При переходе пользователя с экрана Dashboard в раздел Wallets, добавлении нового кошелька и последующем возврате на Dashboard (`nav_to("dashboard")` / `switch_screen("dashboard")`), список кошельков в панели `#panel-wallets` остаётся в устаревшем состоянии («No wallets tracked yet»). Пользователь не видит добавленный кошелёк, пока принудительно не нажмёт горячую клавишу ручного обновления (`r` / `action_refresh`).

Причина заключается в несоответствии обработчиков жизненного цикла Textual: в `DashboardScreen` логика обновления была ошибочно повешена на метод `on_show(self)`, ожидая, что он вызывается при каждом показе экрана (`"""Refresh data whenever the screen becomes visible (e.g. after adding a wallet)."""`). Однако в Textual при переключении обратно на уже смонтированный экран через `switch_screen` возникает событие `events.ScreenResume`, а не `Show`. Метод `on_screen_resume` в `DashboardScreen` отсутствует, из-за чего вызов `refresh_data()` не инициируется.

## Шаги воспроизведения
1. Запустить приложение с чистой БД: `WIT_DB_PATH=/tmp/qa_e2e.db` в окне терминала (140x40).
2. Перейти в экран Wallets (`app.nav_to("wallets")`).
3. Добавить в базу данных новый кошелёк (адрес `0x111122223333444455556667777888899990000a`, имя `TestWallet1`, сеть EVM).
4. Вернуться на экран Dashboard (`app.nav_to("dashboard")`).
5. Проверить содержимое виджета `#panel-wallets`.

## Ожидание / Факт (RU)
- **Ожидание:** В панели `#panel-wallets` отображается строка с добавленным кошельком (`TestWallet1` / `0x1111...000a`).
- **Факт:** Панель `#panel-wallets` отображает сообщение `No wallets tracked yet (press 'a' to add or 'i' to import)`.

## Саммари (RU)
Сквозной сценарий добавления кошелька и его немедленного отображения на Dashboard нарушен: фреймворк Textual не вызывает метод `on_show` при повторной активации экрана через `switch_screen`, требуя реализации `on_screen_resume`. Из-за этого данные на главной панели мониторинга остаются устаревшими без ручного рефреша.

## Выводы (RU)
- Дефект имеет критичность S2 (Major), так как ломает базовый пользовательский путь отслеживания состояния портфеля после манипуляций с кошельками.
- Для устранения необходимо в `DashboardScreen` добавить обработчик `on_screen_resume(self)` с вызовом `self.refresh_data()`.
- Согласно ограничениям роли QA продуктовый код оставлен нетронутым; после реализации фикса разработчиком баг должен быть верифицирован повторным запуском `test_wallet_add_flow.py`.
