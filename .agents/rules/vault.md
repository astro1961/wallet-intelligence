# Правило: ведение vault

Действует всегда, без вызова скилла.

## 1. Источник истины
- Требования читать из `vault/01-Requirements/`, этапы — из `vault/02-Plan/`.
- Если требование/этап отсутствуют — не выдумывать, завести по шаблону и пометить `_TODO_`.

## 2. Любое действие → запись
- Каждый значимый шаг (прогон тестов, найденный баг, фикс) фиксируется в vault.
- Журнал этапа `vault/03-Logs/LOG-STAGE-NN.md` — **append-only**, старые записи не переписывать.

## 3. ID и связи
- ID берётся как «максимум в папке + 1», формат — из `vault/00-Conventions.md`.
- Связи — Obsidian wiki-links в frontmatter: `requirement: "[[REQ-003]]"`, `stage: "[[STAGE-02]]"`,
  `fix: "[[FIX-005]]"`, `bug: "[[BUG-007]]"`.

## 4. Формат документов
- YAML frontmatter + тело по шаблону из `vault/_templates/`.
- В конце — обязательные русские блоки **«## Саммари (RU)»** и **«## Выводы (RU)»**.

## 5. Запреты
- Не удалять и не переписывать историю в `03-Logs/`.
- Не закрывать баг без зелёного прогона и повторной проверки.
- Не править продуктовый код из QA-агента.
