# Vault keeper

## Структура
`00-Home`, `00-Conventions`, `01-Requirements`, `02-Plan`, `03-Logs`, `04-Bugs`, `05-Fixes`,
`06-Notes`, `07-Tests`, `_templates`. Связи — Obsidian wiki-links `[[...]]`, таблицы — Dataview.

## Выдача ID
1. Открой папку нужного типа (`01-Requirements/` для REQ, `04-Bugs/` для BUG, …).
2. Найди максимальный существующий номер.
3. Новый ID = максимум + 1 (формат из `vault/00-Conventions.md`).
4. Если работает несколько агентов параллельно — новые записи заводит только qa-engineer (избегать коллизий).

## Создание документа
1. Скопируй шаблон из `vault/_templates/<Type>.md`.
2. Замени плейсхолдеры: `NNN`, `YYYY-MM-DD`, статус.
3. Проставь связи в frontmatter wiki-links:
   - Bug: `requirement: "[[REQ-003]]"`, `stage: "[[STAGE-02]]"`, `fix: "[[FIX-005]]"`
   - Fix: `bug: "[[BUG-007]]"`, `verified_by: "[[RUN-...]]"`
   - Run: `stage: "[[STAGE-02]]"`
4. Допиши запись в журнал `03-Logs/LOG-STAGE-NN.md` (append-only) со ссылками `[[BUG-007]]`.
5. Обнови `00-Home.md` (текущий этап, открытые баги) и дашборды (Dataview обновляются сами).

## Закрытие бага
1. Убедись, что есть зелёный прогон (`RUN-...` в `07-Tests/`).
2. `status: verified` → после повторной проверки `status: closed`.
3. В `FIX-NNN` поставь `verified_by: "[[RUN-...]]"`.

## Правила
- Не переписывать историю журналов.
- Каждый документ заканчивается блоками **Саммари (RU)** и **Выводы (RU)**.
- Битая ссылка `[[...]]` = дефект документации, чини сразу (workflow `/vault-init`).
